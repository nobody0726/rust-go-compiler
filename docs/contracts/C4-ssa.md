## 1. 已验证的部分

### 1.1 值的唯一定义点

**验证来源**：`T-S2-01`

```rust
pub struct ValueId(usize);   // 新类型，不可与别的语义混用
```

「唯一定义点」在 M0 是**结构性事实**而非约定：`ValueId` 只能由
`Builder::define` 产生，而 `Builder` 是线性使用的。

⚠️ **该保证的范围**：它只在**单块直线程序**内成立。
多块时「唯一定义点」需要 phi 机制配合 —— 见 §3.2。

### 1.2 使用先于定义（结构性保证）

**验证来源**：`T-S2-01` + 测试 `定义顺序保证_使用先于定义`

`Builder::expr` 用**后序遍历**：

```text
Bin { op, lhs, rhs }  ⇒  ① 先 lower(lhs)  ② 再 lower(rhs)  ③ 最后建本条指令
```

因此指令序列里「引用的 ID 必然小于自己的 ID」。

**为什么不能写成先序**：先序会先建 `v0 = bin(...)` 再 lower 两侧，
于是出现「`v0` 引用了还不存在的 `v1`」⇒ 求值时 `env.get` 落空。

**M0 的范围内**，`id` 严格递增 + 引用 ID 更小 ⇒ 求值可以**单遍线性扫描**完成。
**多块时不成立**（块间可以互相引用）—— 那时要靠 phi + 支配关系。

### 1.3 确定性与可复现

**验证来源**：`T-S2-01`（三次结果逐字节相同，E6）

块表用 `BTreeMap` 而非 `HashMap` —— **顺序必须确定**。
理由与 C1 §4.2 相同：若顺序依赖哈希迭代序，E6 的「三次一致」会随机失败，
而这种失败**极难定位**（看起来像随机性）。

> 诊断排序靠 `code` 兜底（因为同一位置可能有多条诊断）；
> 而**块表**没有第二排序键可用，所以直接选有序容器。

## 2. 需求登记（`03` §4 第 5 条要求识别 memory / tuple / 调用边界）

每条需求都带**触发形状**（具体到能写成一个测试）——
只写「需要 memory 模型」是空话，任何人重写 M6 时都能再写一遍。

### 2.1 `S2-NEED-MEMORY` —— memory（可变内存 / 别名）

| 项 | 内容 |
|---|---|
| **触发形状** | `func f() { a := 1; p := &a; *p = 2; return a }` |
| **为什么图不够** | Block/Value 图里每个值**不可变且唯一定义**。`a` 被 `*p = 2` 改写后，它的值取决于「谁最后写」，这与 SSA 的「值不变」**直接冲突**。必须引入显式的 memory SSA 形式（内存作为**另一个** SSA 值，load/store 作为带副作用的指令），否则别名分析无处安放 |
| **M0 处置** | **不实现**。fixture 是纯表达式，无可变状态。本条只登记 |
| **归属** | **M6** |

### 2.2 `S2-NEED-TUPLE` —— tuple（多返回值）

| 项 | 内容 |
|---|---|
| **触发形状** | `func two() (int, error) { return 1, nil }` |
| **为什么图不够** | Go 的多返回值是**语言级 tuple**（可整体赋值、可直接传参、可出现在 range 与赋值左侧），不是结构体。SSA 的值是**单个**的 ⇒ 要么给每个返回值各自一个值并在调用点建一组「结果向量」，要么引入 bundle 类型。前者会让调用边界与赋值边界都变复杂 |
| **M0 处置** | **不实现**。三个 fixture 都不含多返回值 |
| **归属** | **M5b**（`03` §M5b 明确列了「多返回值」） |

### 2.3 `S2-NEED-CALL` —— 调用边界

| 项 | 内容 |
|---|---|
| **触发形状** | `println(1+2)` —— 参数在进入内建之前就已是值 |
| **为什么图不够** | M0 的 HIR 把内建实参存成**已求值的 `Val`**（`rgoc_hir::Stmt::Print`），于是**调用边界画在 HIR 层，S2 的图里看不到调用**。真实编译里调用边界是三件事的重合：① 传参约定（栈/寄存器）② 调用点之后的控制流（被调用方可能不返回）③ 结果的接收方式。这三件事都要求调用在图里**显式存在**，否则 SSA 的控制流边无从画起 |
| **M0 处置** | **只记录，不实现**。当前形态让 S1/S2 能专注比较求值结果；但**必须写明这是个简化**，否则 M6 会误以为调用边界已解决 |
| **归属** | **M6**（调用与调用边）；**M5**（Go 侧调用语义） |

### 2.4 `S2-NEED-PHI` —— phi（块参数 / 支配）

| 项 | 内容 |
|---|---|
| **触发形状** | `func f(c bool) int { if c { return 1 }; return 2 }` |
| **为什么图不够** | 分支汇合处同一个「逻辑变量」有**两个定义点**。SSA 用 **phi 指令在块入口选值**来恢复「唯一定义」。本子集无分支，`Block::params` 刻意留空作为**容身处**，这样 M6 接手时能看到「phi 该挂在哪里」，而不是重新发明 |
| **M0 处置** | **不实现**。`Block::params` / `Block::succs` 字段已留位（恒空） |
| **归属** | **M6** |

### 2.5 `S2-NEED-VERIFIER` —— verifier（图不变式检查）

| 项 | 内容 |
|---|---|
| **触发形状** | 任何多块的图 —— 本 spike 只有一个块，所以**触发不了** |
| **为什么图不够** | SSA 的正确性依赖一组不变式：唯一定义点、使用先于定义、类型一致、phi 位于汇合处。这些必须**被检查**而不是被信任 |
| **M0 处置** | **不实现**（`M0-tests.md` §5.2 T-S2-03 明确「不要求 M0 实现 verifier」）。差距见 §3 |
| **归属** | **M6**（verifier 是 M6 的门禁内容之一） |

## 3. 与 M6 完整 verifier 的差距（`T-S2-03`）

| 不变式 | 状态 | 说明 |
|---|---|---|
| 唯一定义点 | ✅ 具备 | `ValueId` 是不可变新类型，`Builder::define` 是唯一 ID 来源 |
| 使用先于定义 | ✅ 具备（**直线程序内**） | 后序遍历 + 顺序求值。⚠️ 多块时**不再成立** |
| 控制流图 | ❌ 不具备 | 只有一个块，`succs` 恒空。没有分支就没有边，也就没有「汇合」概念 |
| phi 正确性 | ❌ 不具备 | 没有 phi 指令，也没有块参数。`Block::params` 只是**容身处** |
| **支配关系（dominator）** | ❌ 不具备 | **单块图里支配关系是平凡的（全可达），因此从未被验证过** —— 这是最容易「以为自己已经会了」的一项 |
| 类型一致性 | ❌ 不具备 | `eval_bin` 遇到非整数返回 `Err`（**运行时**检查），但图**本身没有类型标注** ⇒「两个 i32 相加」与「i32 加 string」在图里**长得一样** |
| 副作用 / 内存 | ❌ 不具备 | 指令全是纯函数（const / bin）。没有 load/store ⇒ 无法检查「先写后读」的顺序 |
| 调用指令 | ❌ 不具备 | 图里**没有 call 指令** —— print 的实参在 HIR 层已是值 |

> **「不具备」与「从未被验证过」必须分开读**。
> 单块图里很多性质是**平凡成立**的（trivially true），
> 那不构成「已支持」的证据 —— 只构成「还没被证伪」。

## 7. 五项需求的兑现（M6）

每条都指到**决策**、**代码**、**判据**三处 —— 只写「已支持」是空话，任何人重写一遍都能再写一次。

### 7.1 `S2-NEED-MEMORY` → 按根分区的 memory SSA

| 项 | 内容 |
|---|---|
| **决策** | `D-M6-5`（按根分区：`Root::Global` / `Root::Slot` / `Root::Heap`）+ `D-M6-6`（指针是**普通值**，根标注在 `Load`/`Store` 上） |
| **形状** | `Instr::Load { dst, mem, root, addr, typ }` / `Instr::Store { dst, mem, root, addr, val }`：`Store` **产出新的 mem**，同根的读写靠 mem 链保序 |
| **代码** | `rgoc-ssa/src/{ir,build}.rs`（`store_root` / `store_to_unknown` / `mem_of`）；运行期在 `rgoc-interp/src/ssa_exec.rs` 按**真实地址**（`Value::Ptr` 的 `Cell`）访存，`root` 只用于静态定序 |
| **判据** | `V6`（mem 支配 + 同块序）；`T-SSA-07`（反例）；`T-SSA-25`（写穿后读同一条 mem 链）；`T-SSA-36`（跨函数写穿）；`T-SSA-49`（变异：`Store` 不产出新 mem ⇒ 红） |

**根归属是构造性的**（`Fb::ptr_root`）：只认 `AddrOf` / `Field` / `Index` / 指针转换；合并值、形参、调用结果一律「根未知」⇒ 写操作**扇出到所有根**（`store_to_unknown`）。猜堆根是静默丢写。

### 7.2 `S2-NEED-TUPLE` → 多结果指令（tuple 不进 IR）

| 项 | 内容 |
|---|---|
| **决策** | `D-M6-4`：多返回值 = **多结果指令**（`Instr::Call { dsts: Vec<ValueId> }`），tuple 不作为值存在 |
| **形状** | `a, b := two()` ⇒ `v3, v4 = call func#1()`；`return f()` 直连（不落中间槽）；`g(f())` 实参直连 |
| **代码** | `rgoc-ssa/src/build.rs`（`emit_call` / `expr_multi`） |
| **判据** | `V5`（结果个数 == 签名）；`T-SSA-20/21/22`；`T-SSA-50`（变异：只取第一个结果 ⇒ 红） |

### 7.3 `S2-NEED-CALL` → 显式调用边界 + effect 摘要

| 项 | 内容 |
|---|---|
| **决策** | `D-M6-9`：调用的副作用**显式声明**（`Effect { writes, writes_all, may_panic, may_call_back, prints }`） |
| **形状** | `Instr::Call { dsts, callee, args, dots, effect }`；`CalleeRef::{Func, Method{recv,func}, Builtin, Indirect}`；`dots` 区分 `append(s, xs)` 与 `append(s, xs...)`（`R-35-1`） |
| **代码** | `rgoc-ssa/src/{ir,build,effect}.rs`；求值器 `Call` **只压帧**，`Return` 时先全读、再弹帧、再写调用方的 `ret_to`（递归不吃宿主栈） |
| **判据** | `V5`（结果数/实参数与签名一致）；`T-SSA-23`；`T-SSA-29`（变参）；`T-SSA-30`（方法调用）；`T-SSA-50` |

### 7.4 `S2-NEED-PHI` → 块参数（不用 phi 指令）

| 项 | 内容 |
|---|---|
| **决策** | `D-M6-3`：phi = **块参数**（`Block.params` + 前驱在终止符里给实参） |
| **形状** | `term if v0 -> b1 () \| b2 (v1)` + `block b2 params=[v3]`；`a, b = b, a` 在多轮 copy 后仍正确 |
| **代码** | `rgoc-ssa/src/build.rs`（`join_into` / `join_branches` / `short_circuit` 的 `lead` 参数）；`ssa_exec.rs::jump`（**先全算边实参、再全写块参数**） |
| **判据** | `V7`（实参个数 == 参数个数）；`V2`（支配，块参数是汇合点的定义）；`V4`（边与 preds/succs 互逆）；`T-SSA-08/16/28`；`T-SSA-52`（变异：顺序赋值 ⇒ 红，手搓回边对调） |

### 7.5 `S2-NEED-VERIFIER` → 九条不变式

| 项 | 内容 |
|---|---|
| **决策** | `D-M6-11`：反例必须是**手写 IR**（由构建器产出的反例等于用被测物证明被测物） |
| **形状** | `verify(&SsaFunc, &TypeTable) -> Result<(), VerifyError{invariant, block, idx, detail}>`，`V1..V9` 固定顺序 |
| **代码** | `rgoc-ssa/src/{verify,typing,cfg,dom}.rs` |
| **判据** | `T-SSA-02..12`：**32 条反例**（每族至少一条，全部被拒且带 `block`/`idx`）+ **16 条正例**（合法图全过 —— 反向证明 verifier 不是一律拒）；`T-SSA-47/48`（变异：删 `V7` / 短路 `V2` ⇒ 红） |

| 不变式 | 查什么 |
|---|---|
| `V1` | 每个值**恰好**一个定义点（块参数或指令 `dst`） |
| `V2` | 使用点的定义必须**支配**它（`mem` 操作数除外 —— 归 `V6`，`R-12-2`） |
| `V3` | 类型一致（`Bin`/`Un`/`Convert`/`If` 条件/块参数交接） |
| `V4` | CFG 互逆：边指向存在的块、同一目标的两条边实参一致、入口无前驱 |
| `V5` | 调用结果数 / 实参个数与签名一致（「查不了」不许当通过） |
| `V6` | mem 操作数被支配 + 同块内按程序顺序 |
| `V7` | 边实参个数 == 目标块参数个数 |
| `V8` | 没有不可达块 |
| `V9` | 取过地址的槽必须有根登记 |

## 8. §3 差距表的逐行关闭

| 不变式 | §3 的状态 | M6 的结论 |
|---|---|---|
| 唯一定义点 | ✅ 具备 | ✅ 保持，并由 `V1` **检查**（不再只是结构性事实） |
| 使用先于定义 | ✅ 直线程序内 | ✅ 升级为 `V2` 支配检查（跨块也成立） |
| 控制流图 | ❌ | ✅ `cfg.rs` 现算 `preds/succs/edge_args`；`V4`/`V8` 检查 |
| phi 正确性 | ❌ | ✅ 块参数 + `V7`/`V2`（见 §7.4） |
| 支配关系 | ❌「从未被验证过」 | ✅ `dom.rs` 手写 CHK 算法；`V2` 是它的第一个消费者 |
| 类型一致性 | ❌ | ✅ `V3` + `typing.rs`（`identical` 判等，不比 `TypeId` 下标） |

| 调用指令 | ❌ | ✅ §7.3 |

> **一条仍然成立的边界**：verifier 只检查**图的不变式**，不检查「这张图是否等价于源码」。
> 后者是 `SSA-4` 的三方差分（`HIR = SSA = go run`）负责的 —— 两者不能互相替代。

## 9. M8 为什么不改本契约（2026-10-25 记）

M8 给 HIR 加了六个并发节点（`C3` §6），SSA 侧**一条都不接** —— 这不是遗漏，是既有决定：

| HIR 新节点 | SSA 侧行为 | 依据 |
|---|---|---|
| `Stmt::Go` / `Stmt::Send` / `Stmt::Select` / `ExprKind::Recv` | `SSA-UNSUPPORTED-CHAN`（建图前拒） | §7.1 的 memory 模型没有「谁在跑」这个维度 |
| `RangeKind::Chan` | `SSA-UNSUPPORTED-CHAN` | 同上 |
| `RangeKind::Func` | **没有专属码了**：M8/Task 45 起 HIR 把 range over func 下降成「调用 + 合成函数字面量」，SSA 看到的是 `SSA-UNSUPPORTED-FUNC-VALUE` | `SsaCode::RangeFunc` 已删（`ALL` 9→8）—— 产不出来的码一律删 |

**三方差分因此退化为两方**：chan 语料上 `--via=ssa` 恒被拒，
`run-chan.sh` 只做 `run` vs `go run`。这一点写进 `M8-report.md` §4，
**不许**说成「三方差分绿」。

**本契约的 §1–§8 一字未改**：并发的语义全在 `C11`（运行期），
SSA 的形状（tuple / memory / phi / 支配）与并发无关 —— 一个单线程 IR
不需要「谁来跑」的概念。
