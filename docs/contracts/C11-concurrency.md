# C11 契约：解释器并发（调度 / 通道 / select / 死锁）

> ## 本契约把「并发怎么跑」冻结成**可判定**的规则
>
> M8 的门禁（`CON-1..9`）要求：无缓冲 handoff、缓冲 FIFO、close 三态、select 五形态、
> 死锁与退出可区分、**同 seed 逐字节可回放**。这六件事都不是「跑通就行」——
> 每一条都有多种同样能跑通的实现，而它们的可观测行为不同（谁先跑、哪个 case 被选中、
> 死锁判不判）。不冻结就会有第二种解释。
>
> **实现落点**：`rgoc/crates/rgoc-interp/src/sched.rs`（`Shared`/`G`）、
> `rgoc/crates/rgoc-interp/src/chan.rs`（`ChanObj`/`Waiter`）。
> **消费者**：M8 的全部判据、M8 之后的所有解释器改动；**M9d** 的 native 调度契约会**参照**本文档，
> 但**不承诺**与它同构（native 是多核 + 抢占，这里是单线程）。
>
> **与 `C9` 的关系**：`C9` 管**值怎么打印、退出码是几**；本契约只管**谁来跑、什么时候跑**。
> 两者在「死锁」「goroutine 内 panic」两处相接，那两行的**结论**记在 `C9` §5，本文档只解释**为什么**。

**状态**：**正式（已定稿）**（2026-10-25，M8 / Task 64 —— 执行期的 14 条 `R-8-*` 已折回正文，见 §7）
**契约级别**：正式（改动必须走 `M8-tests.md` §9 的修订流程，并在 §7 留一行）
**冻结范围**：调度顺序、通道四操作、select 三阶段、死锁判定、不承诺清单。
**不冻结**：数据结构（`ChanObj` 的字段名）、实现细节（怎么存等待队列）、性能

## 2. 调度

### 2.1 三条硬规则（冻结）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **M:1**：M 个 goroutine 跑在 **1 个** OS 线程上 | 真并行会让「同 seed 同结果」不可实现 |
| 2 | **不抢占**：只在**阻塞点**（`recv` / `send` / `select` 无就绪）让出 | 按步数抢占会让 `(源码, seed, 预算)` 不再唯一决定执行（`M8-design.md` `D-M8-13`） |
| 3 | **就绪队列 FIFO**：`go` 创建的、被唤醒的，一律**入队尾** | 单就绪时交错固定 ⇒ 输出可复现 |

> **单线程的直接后果**：这里**没有数据竞争**这回事 —— 两个 G 不会同时读写同一个 `Cell`，
> 它们只会**先后**读写。所以本契约不提供 `-race`（§6 第 4 条）；「竞态」在这里表现为
> 「某种交错」，而交错由 §2.2/§2.4 完全决定。

### 2.2 「当前 goroutine 一直跑」

```text
一条 goroutine 被选中后，一直跑到它 Blocked 或 Exited，才换下一个。
`go f()` 只把新 goroutine 入队尾，**不切走**当前 goroutine。
```

推论（要写进使用者的脑子）：`for {}` 在 goroutine 里**不会**被切走，只会烧完步数预算
（`C9` §6）然后退出码 2。这与官方运行时不同（官方会异步抢占），见 `U-M8-01`。

### 2.3 让出与唤醒

| 事件 | 行为 |
|---|---|
| 当前 G 阻塞 | 从 `runq` 弹队首；队列空 ⇒ 走 §5 的判定 |
| 当前 G 退出 | 丢弃它的全部状态；**不跑**它的 defer（`defer` 在正常退出前已跑） |
| 某 G 被唤醒 | 只入队尾、清 `blocked`；**不保证**它立刻跑 |
| `main` 返回 | **立即**结束进程（§5.1）；队列里的 G 全部丢弃 |

> **时间不是本契约的维度**：没有超时、没有 `Sleep`、没有定时器（§6 第 5 条）。
> 唯一的「资源」是**步数**与**帧深**（后者按 G 计、上限 1000，§6 第 6 条）——
> 所以「等 3 秒」这类程序在这里要么编不过（无 stdlib），要么永远等下去（死锁）。

### 2.4 seed 与可回放

| 项 | 规则 |
|---|---|
| 输入 | `(源码, seed, max_steps)` **唯一**决定一次执行 |
| `seed == 0` | select 多就绪时取**源码顺序的第一个**（§4.3） |
| `seed != 0` | 用 `xorshift64` 从「可做的 case」里选；**同一 seed 同一次执行** |
| 不记录 | **不记事件日志**（§6）；回放靠重跑，不靠日志 |
| 步数 | **全局累计**（所有 G 共用一个计数）——否则 N 个 G 各跑满预算会让预算失效 |

## 3. 通道

### 3.1 状态

```text
ChanObj {
  elem,        // 元素类型（决定深拷贝的形状）
  cap,         // 容量；无缓冲 = 0
  buf,         // 环形缓冲，len(buf) <= cap
  closed,      // 是否已关闭（单向：false → true）
  sendq, recvq // 等待队列（FIFO）
}
Waiter { g, token, slot, done }
```

- `slot`：阻塞的**发送方**放它的值；阻塞的**接收方**留空（等对端填）。
- `done`：**唯一**的「我这一侧已完成」判据。醒来重试时先看它，不看重试次数。

### 3.2 四个操作（冻结，按顺序判）

**recv**

| 序 | 条件 | 动作 |
|---|---|---|
| ① | `buf` 非空 | 从 `buf` 取出；**若 `sendq` 非空**，把队首发送方的值搬进 `buf` 并唤醒它（保持 buf 满） |
| ② | `sendq` 非空 | 直接取发送方的 `slot`，置 `done`，唤醒它 |
| ③ | `closed` | 返回**零值** + `ok = false` |
| ④ | 其余 | 登记 `Waiter`（`slot = None`）到 `recvq`，阻塞 |

**send**

| 序 | 条件 | 动作 |
|---|---|---|
| ① | `closed` | `panic: send on closed channel` |
| ② | `recvq` 非空 | 直接把值放进队首接收方的 `slot`，置 `done`，唤醒它 |
| ③ | `cap > 0` 且 `buf` 未满 | 入 `buf`，完成 |
| ④ | 其余 | 登记 `Waiter`（`slot = Some(值)`）到 `sendq`，阻塞 |

> ⚠️ **`closed` 必须排在「buf 未满」之前**。官方 `chansend` 加锁后的第一件事就是
> `if c.closed != 0 { panic }`（`runtime/chan.go:224`）。若把它排在 `buf` 之后，
> `close(c); c <- v`（`cap > 0` 且缓冲未满）会**静默把值塞进缓冲** ——
> 不 panic、不报错，只是那笔发送消失了。

**close**

| 序 | 条件 | 动作 |
|---|---|---|
| ① | `closed` 已为真 | `panic: close of closed channel` |
| ② | 其余 | `closed = true`；唤醒 `recvq` **全部**（它们重试时按 recv 的 ①→③ 先**排空 buf**，排空后才拿零值）；唤醒 `sendq` **全部**（它们重试时看到 `closed`，在**自己的** G 里 `panic: send on closed channel`） |

**len / cap**

| 操作 | 值 |
|---|---|
| `len(c)` | `buf.len()`（阻塞发送方的值**不算**，它在 `Waiter.slot` 里） |
| `cap(c)` | `cap`（无缓冲 = 0） |

### 3.3 值语义（冻结）

**双次深拷贝**：`send` 时拷一份进 `slot`/`buf`，`recv` 时再拷一份交给接收方。

少了第一次：`ch <- a; a[0] = 9` 会改到接收方看到的东西。
少了第二次：接收方 `v[0] = 7` 会改到缓冲里，下一个接收方看到 7。

### 3.4 nil 通道

| 操作 | 行为 |
|---|---|
| `<-c` / `c <- v`（`c` 是 nil） | **永久阻塞**（不是 panic）；**不登记**（没有队列可登记） |
| `close(nil)` | `panic: close of nil channel` |

## 4. select

### 4.1 三阶段（冻结）

| 阶段 | 做什么 |
|---|---|
| **① 求值** | **所有** case 的通道表达式、**所有** send 的右值，按源码顺序**各求值一次**。走 `default` 时也要求值过（`STM-15` 的原文） |
| **② 试探** | 按源码顺序扫描：`nil` 通道**跳过**（永不就绪）；`default` 记「有」；就绪的记「可做」 |
| **③ 阻塞** | 没有任何「可做」：有 `default` ⇒ 走它；否则给**每个非 nil** 的 case 登记 waiter（**共用一个 `token`**）并阻塞 |

### 4.2 撤销（冻结）

被任一通道唤醒后：

1. 拿 `token` 去**所有**相关队列里删掉自己（删不到也算成功 —— 对端可能已经取走）；
2. 按「哪个 waiter 的 `done` 为真」定 winner；
3. 只有 winner 的 body 跑；其余 case **一次都不跑**。

**重复 channel**（`case <-c:` 与 `case v := <-c:` 同时存在）就是这条的判据：
两个 waiter 各自独立登记，被唤醒时**只有一个** `done`。

### 4.3 多就绪时的选择（冻结）

| `seed` | 规则 |
|---|---|
| `0`（默认） | 取**源码顺序的第一个**可做 case |
| 非 0 | `xorshift64` 从「可做」里选 |

**与 `STM-15` 的偏离**：官方是「均匀随机」，但同一份 spec 也写「程序不得依赖」。
我们固定一种实现，取**最可复现**的那一种 —— 见 `U-M8-02`。

### 4.4 空 select

`select {}`：没有 case ⇒ 阻塞且**没有任何队列**可登记 ⇒ 立即按 §5.2 判死锁
（不是「烧到预算超限」）。

## 5. 死锁与退出

### 5.1 `main` 返回

`main` 的帧栈空 ⇒ **立即**结束进程：

- 退出码 `0`；
- `runq` 里与阻塞中的 G **全部丢弃**，**不跑**它们的 defer（官方语义：进程退出）；
- 不做「等 goroutine 跑完」——那是错的实现，且会让 `T-CON-36` 挂死。

### 5.2 死锁

判定条件（三条**同时**成立）：

1. `runq` 空；
2. 存在至少一个 `blocked` 的 G；
3. `main` 未结束。

⇒ stderr 一行 `fatal error: all goroutines are asleep - deadlock!`，退出码 `2`。
**不进合并流**（它不是 Go 的 `panic`），所以不参与 `println` 的字节顺序。

### 5.3 panic 与 goroutine

| 情形 | 行为 |
|---|---|
| G 内未捕获 panic | **整个程序**退出码 2；不包装、不改写 panic 值（`U-M8-08`） |
| 其它 G 的 defer | **不跑**（进程直接终止） |
| G 内 recover | 只在**它自己**的 defer 里有效（`C3` 的既有规则，M8 不改） |

## 6. 不承诺（六条）

| # | 不承诺 | 后果（使用者会看到什么） | 对应白名单 |
|---|---|---|---|
| 1 | **不记事件日志** | 无法「回放另一次调度」。要做只能重跑；§2.4 是唯一的回放口径 | — |
| 2 | **不抢占** | `for {}` 在 G 里烧到预算超限（退出码 2），不会让 main 有机会跑完 | `U-M8-01` |
| 3 | **select 不均匀随机** | 多就绪时永远取源码顺序（seed=0），不模拟官方的随机 | `U-M8-02` |
| 4 | **无 `-race`** | 单线程线性化，「竞态」在我们这里表现为**某种交错**，检测不到数据竞争 | `U-M8-07` |
| 5 | **无定时器** | `time.Sleep` / select 超时不存在；引入墙钟会毁掉 §2.4 | `U-M8-05` |
| 6 | **无 goroutine 栈增长** | 帧深上限 1000，按 G 计；超了退出码 2 | `U-M8-06` |

> **自洽要求**：这六条在 §2–§5 的正文里各有痕迹（1 → §2.4；2 → §2.2；3 → §4.3；
> 4 → §2.1 的「没有数据竞争」；5 → §2.3 的「时间不是本契约的维度」；6 → 同上）。
> 新增一条不承诺，必须先在正文里补它的痕迹 —— 否则它就只是「声明」而不是「契约」。
