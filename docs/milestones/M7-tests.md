## 3. 测试 ID 全表

### 3.1 甲腿：帧与 ABI（`S`+`H`，11 条）

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-NAT-01` | 槽宽与类型 | `bool`/整数/指针/`float64` = 8；`complex128` = 16；数组/struct = `size_of` 向上取 8 的倍数。逐个类型各一条：**相邻槽互不覆盖**（写入 A 后读 B，B 的字节不变） |
| `T-NAT-02` | 对齐与零大小类型 | 8 字节对齐；`struct{}` 与 `[0]int` 占 **0 字节**但仍有地址（`zerosize.go` 形态：两个零大小变量地址可相等，不许崩） |
| `T-NAT-03` | 零值 | `slot_types` 里的槽进帧即清零：`var a [3]int` / `var s S` / `var p *T` 读出全 0（不是垃圾） |
| `T-NAT-04` | 帧大小与序言一致 | `FRAME-MAP v1` 的 `frame=` 必须等于 `objdump` 里 `sub sp, sp, #N` 的 `N`；两者不一致即红（防「表里一套、代码一套」） |
| `T-NAT-05` | 栈对齐 16 | 进入函数时、每次 `bl` 前、每次 `svc` 前 `sp % 16 == 0`。判据 = 用一条**奇数个 8 字节实参**的调用去触发（不对齐会崩或读到错值） |
| `T-NAT-06` | 并行拷贝：二值交换 | `a, b = b, a` 后 `a` 是原 `b`、`b` 是原 `a`（**必须**用交换环，不能靠「先读后写」碰巧对） |
| `T-NAT-07` | 并行拷贝：三值轮换 | `a, b, c = b, c, a`；环长 3，必须用临时槽打断 |
| `T-NAT-08` | 并行拷贝：无环 | 目标与源互不相交时直搬；且**不得**多写（用一条「某个源在搬完后被覆盖」的形态证明顺序无关） |
| `T-NAT-09` | 聚合按指针传 | `func f(s S)` 里改 `s.x` **不影响**调用方的 `s`（值语义）；`func f(s *S)` 里改则影响 |
| `T-NAT-10` | 多返回值顺序 | `func f() (int, float64, int)` ⇒ `x0`/`v0`/`x1`（**两个序列独立计数**）；三个结果各取一个可区分的值 |
| `T-NAT-11` | 超过 8 个实参 | 9 个 `int` 实参：前 8 个进 `x0..x7`、第 9 个走调用方 outgoing 区；被调方读到的顺序正确 |

## 4. 判据细节

### 4.1 三方差分（唯一语义判据）

```text
rgoc build <file> -o prog  &&  ./prog   ==   rgoc run --via=hir   ==   go run
合并流逐字节；退出码相同；唯一容差 \r\n → \n
```

**为什么不是四方**：`--via=ssa` 那条腿 M6 已经证过 46/46 一致（`T-SSA-32`），再比一遍只是在测同一件事。
但 `T-NAT-55` 保留「M6 的两条通路仍一致」作为**回归**，防止 M7 改动把上游弄坏。

**为什么三方差分不能单独当 M7 的判据**：42/46 输出为空（`F5`），三条腿在这 42 个上
「都输出空 + 都退出 0」——**同时绿不证明算对了**。所以 §4.2 强制分两栏报。

### 4.2 有输出 / 空输出必须分两栏（M7 特有的判据风险）

| 栏 | 文件数（预估） | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 有输出 | **4** | 输出字节正确（算术、格式化、字符串、复数） | 覆盖面窄 —— 只有 4 个文件 |
| 空输出 | **42** | 程序跑完、退出码 0、不崩 | **完全不证明算对了** |

**纪律**：`T-NAT-41` 的汇总行必须写「有输出 4/4 + 空输出 42/42」，**不许**写「46/46 绿」了事。
带真输出的判据由 `S` 腿的 fixture 承担（§3.3 的九条全部有真输出）。

### 4.3 切片（`T-NAT-40`）

```text
候选（M6 的 N）= 46
N' = 能生成且能跑完的个数
M' = 显式拒绝的个数        （每行带 §5 的码）
断言：N' + M' == 46，且 M' 的码集 ⊆ 白名单
```

**预估 40/6**（`F7` 的文本扫描：`[]T` 波及 6 个），**以实测为准**；差异写进 `M7-report.md`。
**反向守卫**：把 `M'` 里任一行挪进 `N'` ⇒ `T-NAT-40` 必红。

### 4.4 可复现（`T-NAT-48/49`）

| 对象 | 判据 | 反向守卫 |
|---|---|---|
| `.s` | 两次生成逐字节相同 | 改成哈希序 ⇒ 必红 |
| ELF | 两次链接逐字节相同 | 去掉 `-Wl,-s` ⇒ 必红（`.strtab` 里的随机 `STT_FILE` 名） |

> `-Wl,-s` 不是「为了让测试通过而放宽判定」（`F2` 的三条佐证：BuildID 三次相同、差异只在
> `.strtab`、剥掉后程序照跑）。`T-NAT-49` 的反向守卫就是这条主张的证据。

### 4.5 `FRAME-MAP v1`（`T-NAT-51`）

三条硬要求：① 格式符合 `C5`（`#` 头行 + 逐行语法 + 确定性排序）；② `frame=` 等于序言的
`sub sp` 立即数（`T-NAT-04` 与它同源）；③ `safepoint` 的 `offs` 覆盖 `SSA-LIVE v1` 在该位点的
**全部**活值 —— 少一个就是栈图漏根（M10 会拿它扫栈）。

### 4.6 资源与预算

| 项 | 值 | 超限形态 |
|---|---|---|
| arena | 1 MiB | `panic: out of arena` + 退出码 2 |
| 单文件编译墙钟 | 30 s（装置约束） | 装置判超时，不算 pass |
| 单文件运行墙钟 | 10 s（沿 M5 口径） | 同上 |
| 帧大小 | 无硬上限；`> 64 KiB` 记 `open_gaps` | 不是错，是可疑 |

### 4.7 白名单纪律

白名单项**不得**记为 pass；每条都有「fixture + 码 + 退出码 1」三件套（`T-NAT-52`）。
「没做」与「拒绝」必须能区分：拒绝是**有码的拒绝**，不是静默跳过、更不是 panic。

## 8. 判定口径的三条纪律（沿 M4/M5/M6 的教训）

1. **不报「大部分绿」**：`N'` 与 `M'` 成对报，`N'+M'=46` 两向断言；有输出/空输出分两栏。

## 9. 修订机制

| 修订 | 日期 | 内容 | 触发 |
|---|---|---|---|
| `R-11-1` | 2026-10-25 | **修 `rgoc_ssa::live` 的漏根缺陷**：safepoint 的 `after[]` 反向扫描种子改为 `live_out ∪ term.uses()`；新增两条回归测试（`T-SSA-55` 的邻居） | 写 `T-NAT-51` 时发现：只在终止符（`return`/`goto`/`if`）里被读的值**不进** `after[]`，于是 `live`/`ptrs` 漏掉它们。M6 的 5 条 liveness 测试没抓到，因为那些用例的返回值同时也被别的指令用过。后果是帧图漏根 ⇒ M10 会把还活着的对象当垃圾回收。变异验证：去掉修复后新回归测试必红 |
| `R-13-1` | 2026-10-25 | 无类型常量按 Go **默认类型**取布局与分类（`untyped int` ⇒ `int`、`untyped string` ⇒ `string`…）；`untyped nil` 仍返回 `None` | `print("hi")` 的 SSA 实参类型就是 `untyped string`；后端不认它，整类程序都编不出来 |
| `R-13-2` | 2026-10-25 | **推翻 `R-8-2`**：`complex64` 占 **2 个 `v`**（`s{vi}` / `s{vi+1}`），不是「打包进 1 个 `v`」 | AAPCS64 对 **HFA 按元素个数**分配寄存器，不是按大小。打包写法要求每次进出都 `fmov` 拆合，且与 `print_value`（读 `s0`/`s1`）不一致。实测 `cplx1.go`：`booltest(5+6i, …)` 的形参是 `complex64`，按 1 个 `v` 传会让被调方读到 0 |
| `R-13-3` | 2026-10-25 | 调用点的寄存器分类由**被调方的形参类型**决定（不是实参类型）；实参与形参精度不同时在边界做 `fcvt` | 无类型复数常量的默认类型是 `complex128`，而形参可能是 `complex64`。按实参走，被调方读到 `d0` 的低 32 位（=0）⇒ 整个 `(0+0i)` |
| `R-13-4` | 2026-10-25 | **帧太小**：`sub sp` 必须覆盖到**最低的槽**（`sub ≥ SAVED + 槽区`）。原写法 `frame_size - 16` 让 `sp` 比最低槽高 16 字节，被调方的 `stp x29,x30,[sp,#-16]!` 正好覆盖那一段 | 实测 `probe5.go`：`show(complex, bool)` 的 `bool` 槽在 `fp-40`、`sp` 在 `fp-32`，`rt_print_complex` 一返回 `bool` 就变 `true`。这个错在「函数里没有调用」时完全看不见 |
| `R-13-5` | 2026-10-25 | 新增：**地址逃逸的取址槽进 arena**（帧里只留 8 字节指针格）。逃逸判定是**保守**的：`return` / 传给非内建函数 / 写进全局或堆 | 帧存储的生命周期是一次调用，`return &T{1}` 两次必须得到不同地址。实测 `compos.go`：`x == y` 为真 ⇒ 自检 panic。判错的代价不对称（漏判 = 静默别名错，多判 = 多几个字节） |
| `R-11-2` | 2026-10-25 | `C5` §8 的 `type=` 改写成 `t<id>`（原示例写 `int` / `complex128`） | 写名字要再造一个类型渲染器，而它必然与 `C7` 漂；`t<id>` 与 `C10` 的类型引用同形 |
| `R-8-1` | 2026-10-24 | 新增前置：**对象布局落 `rgoc-types::layout`**（`layout`/`field_offsets`/`field_offset`）；`T-NAT-01/04/26/51` 的「偏移来自 `rgoc-types`」才有对象可指 | 开工 Task 8 时发现 `rgoc-types` **没有任何布局代码**（解释器用字段**下标**，从不需要字节偏移）——设计稿 §7.3 的「只消费不自算」当时指向一个不存在的东西 |
| `R-8-2` | 2026-10-24 | `C5` §6.1 的复数传参改精确：`complex64` **1 个 `v`**、`complex128` **2 个 `v`**（原写「complex 占 2 个 v」） | `complex64` 是 8 字节、align 4（实测），两个 `f32` 打包在一个 64 位 `v` 里；照原写法会多占一个寄存器，`T-NAT-21` 的实参顺序随之错位 |
| `R-1-1` | 2026-10-24 | ABI 契约**不是新建 `C11`，而是把 `C5-abi.md` 升正式**；`T-NAT-51/62` 与 §4.5 的引用随之改指 `C5` | 开工 Task 1 时发现 `docs/contracts/C5-abi.md` 已存在，标题就是「ABI / frame layout / 对象布局 / runtime symbol bridge」，文件头写明「归属：**M7** 做 MVP、M9 完整化」。新建 C11 会把同一件事写两遍，且让 C5 永远停在 spike 级 |
