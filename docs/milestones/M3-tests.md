> #### ⚠️ 修订 R1（2026-10-16，Task 7 执行期实测发现）—— `T-TY-37` 的「非负**左值**检查」是错的
>
> **原期望**（上表与 `M3-plan.md` Task 7）：`(-1) << 2` 应**报错**（「左值非负检查」）。
>
> **实测**（容器内 go1.27.1，两条独立证据）：
>
> ```text
> $ go run .            # const neg = -1 << 2 ; fmt.Println(neg)
> -4                    # ← 合法，不是错误
>
> go/types 探针：
> a = -4   (type untyped int, exact=true)
> c = -1   (type untyped int, exact=true)     # -1 >> 1，算术右移
> ```
>
> 官方**源码**依据：`go/types/expr.go:625-634` 的左操作数判据是
> `allInteger(x.typ()) || (isUntyped(x.typ()) && ToInt(x.val).Kind()==Int)`
> —— 只要求「是整数」，**没有任何非负要求**；`-1` 是整数 ⇒ 通过。
>
> **真正要检查的是计数（右操作数）**：`expr.go:644-700`，
> `ToInt(y.val)` 为负 ⇒ `InvalidShiftCount`。
>
> **订正后的 `T-TY-37`**：常量移位计数**视为无符号** + 计数**非负**检查。
> 边界（全部实测）：`1 << -1` 拒绝；`1 << 2.0` **接受**（`== 4`，结果类型被改成 `untyped int`）；
> `1 << 1.5` 拒绝；`1 << 2i` 拒绝；`1 << 1074` 接受、`1 << 1075` 拒绝（官方 `shiftBound = 1023-1+52`）。
>
> **代价与已登记项**：`1 << 1074` 这条上界是**官方实现限制**（规范允许），我们照抄以保住
> 「按代号/接受拒绝与 oracle 对撞」。已记进 `.superpowers/sdd/M3-plan/progress.md` 的 Task 7 Ruling，
> 收口时进 `M3-manifest.json` 的 `open_gaps`。

## 5. oracle 口径（`tools/types-oracle`）

### 5.1 adapter

| 项 | 冻结值 |
|---|---|
| 实现 | Go 程序，`go/parser`（**带注释**）→ `go/types.Config.Check`（**不** vendor `internal/*`） |
| 构建 | 容器内 `go build -buildvcs=false`（M2 已踩） |
| 输入 | 与 rgoc **完全相同**的 fixture 文件列表 + `-lang` |
| 输出 | ① 中性类型 dump（C7）② identity 判定 ③ 可表示性判定 |
| 确定性 | 同输入重复运行 **sha256 一致**（`T-TY-95`） |
| **不进对撞** | 位置、诊断**文本**、**约束接口的同一性**（`D-M3-13`） |

### 5.2 C7：中性类型 dump 格式（**冻结**）

> 角色与 C6（AST dump）相同：**两侧按同一份规范化文本对撞**。格式冻结于此；`C7` 契约文件从本小节抽出。

**行式、UTF-8、LF、无 BOM、文件末尾恰一个换行。**

| 规则 | 内容 |
|---|---|
| 注释 / 空行 | 以 `#` 开头的行是注释；空行忽略（两侧都忽略） |
| 每行一条 | `<序号>\t<类型 dump>`；`<序号>` 是**声明顺序下标**（从 `0` 起） |
| 缩进 | 嵌套用 **2 空格**；每个嵌套项**独占一行** |
| **无位置** | 位置一律**不进** dump（另走诊断通道） |
| **名字** | `named`/`alias` 用 **`#<序号>`** 而非名字（避开两侧名字表差异） |
| 字段序 | 按官方结构体**字段声明序** |
| 空 | 无该项写 `-` |
| 布尔 | `true`/`false`（小写） |

**标签集**（与 §3.1 的 `Type` 变体一一对应）：
`basic` `named` `alias` `pointer` `slice` `array` `map` `chan` `struct` `signature` `tuple` `interface` `typeparam` `union` `invalid`

**成对样本的编址（`D-M3-17`）**：写在 fixture 源码里，两侧读**同一份 fixture**：

```go
//rgoc:cmp identical A B
//rgoc:cmp representable 1<<100 int8
```

**修订 R-32-1（Task 32 执行期，2026-10-17；以上示意形态继续有效）**

上面两行是**示意形态**，Task 32 落地时补两点（两条都只是把口语写死，不改语义）：

1. **分隔符**：操作数里**可以带空格**（`chan int`、`struct{ x int }`、`interface{ String() string }`），
   所以再认一种拼写 `//rgoc:cmp <kind> <A> => <B>`。两侧**同一条判据**：先看有没有 `=>`，
   有就按它切（`=>` 不是任何合法 Go 类型表达式 / 常量表达式的子串）；没有就按空白切成**恰好两段**，
   段数不是 2 就**响亮报错**（不是静默跳过）。⇒ 示意形态与 `=>` 形态都能写，不算「两种语义」。
2. **`reject` 的精确触发范围**：`U-M3-05` 的措辞（「约束接口的同一性」）**比实现宽**。
   实现里 `reject` 只在「**两侧都是匿名接口**、且至少一侧含项集或 `comparable`」时出现 ——
   那正是**非有类型集推理不可**的情形。具名的约束接口（`type Num interface{ ~int | ~float64 }`）
   走**具名类型**分支（同名同体 ⇒ 同一、异名 ⇒ 不同一），判定是**正确**的，不构成缺口。
   对撞时排除集按此口径断言（Task 34）。

### 5.3 来源必须标注

每条 golden / 对撞输出都要标注来源（fixture 路径 + `//rgoc:cmp` 行号），便于失败时定位到**具体那一对**。
