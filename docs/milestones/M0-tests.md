### 1.2 完整指令集（16 个）

| 分组 | 指令 | 源码位置 |
|---|---|---|
| 编译/运行 | `compile`、`compiledir`、`build`、`builddir`、`buildrundir`、`run`、`buildrun`、`runoutput`、`rundir`、`runindir`、`asmcheck` | `testdir_test.go:542` |

> `03` §4 要求 harness「枚举所有指令」。上表是枚举的完整依据。

### 1.3 三条必须精确实现的判定规则（带源码出处）

这三点是 harness 的**规格核心**，不能凭直觉实现：

**(R1) 指令行提取** —— `testdir_test.go:502-515`

```text
1. .go 文件不得以换行开头（:497 硬失败）
2. 从头逐行扫描，跳过 //go:build 与 // +build 构建约束行
3. action = TrimSpace(TrimPrefix(line, "//"))   ← 第一个「非空且非构建约束」的行
4. action 为空 → Fatalf("execution recipe not found")
```

> 推论：**不能假定指令在第 1 行**，也不能假定它前面只有注释（`03` §3.1 已警示）。

**(R2) 输出期望判定** —— `testdir_test.go:1169-1193`

```text
期望文件 = <goroot test 目录>/<测试名>.out      ← 注意：在 goroot 下查找，不是测试文件所在目录

① .out 存在 → 与 .out 内容比较
② .out 不存在 → 期望输出为【空】(b = nil)      ← 这就是「官方模式约定」
③ 比较前先把 got 的 \r\n 归一化为 \n
④ 严格相等比较（非模糊、非包含）
⑤ 不匹配时的报错分两种措辞：有 .out（内容不符） / 无 .out（本应为空却非空）
```

> **这条推翻了「缺失 .out 就是任意输出可通过」的猜测** —— 恰恰相反：**缺失 .out 意味着必须无输出**。

**(R3) 诊断切分** —— `testdir_test.go:1195-1213`

```text
splitOutput:
  · 以 \t 开头的行 → 追加到上一行（编译器续行）
  · 以 "go tool" 开头 / "#" 开头 / "<autogenerated>" 开头 → 跳过
  · 仅空白的行 → 跳过
  · 其余非空行 → 作为独立诊断条目
```

**(R4) ERROR 注释解析** —— `testdir_test.go:1432-1499`

```text
errRx     = // (?:GC_)?ERROR (.*)        ← 也支持 // GC_ERROR
errAutoRx = // (?:GC_)?ERRORAUTO (.*)
errQuotesRx = "([^"]*)"                  ← 一行可有【多个】引号模式
lineRx = LINE(([+-])(\d+))?              ← LINE / LINE+n / LINE-n → 替换为 文件:行号

流程：含 "////" 的行 → 跳过（双注释即禁用）
      匹配到 ERROR → 取出所有引号内模式
      每个模式经 LINE 替换后编译为【正则】
      前缀 = <short>:<行号>
```

> 因此 `mainsig.go` 的 `// ERROR "..." "..."` 表示**同一行有两条独立期望**。

**(R5) `errorcheck` 会被自动加内部 flag** —— `testdir_test.go:613-625`

```text
若 flags 中没有 -d= 开头的项 → 自动追加 -d=ssa/check/on
```

> **重要推论**：即使首行是裸 `// errorcheck`（无任何参数），官方驱动也会带上编译器内部 SSA 校验开关。这印证 `03` §3.1 的判断 —— **errorcheck 的期望不能直接当纯语言语义验收**。M0 harness 记录该 flag，但**不得**把它算作「语言级通过」证据。

**(R6) 构建约束过滤** —— `testdir_test.go:517-524`

```text
只看 "\npackage" 之前的 header；shouldTest(header, goos, goarch) 决定 skip
若文件中没有 "\npackage"（故意畸形的用例）→ header = action
```

## 3. E3 —— harness 六类自验

`03` §4 门禁：「harness 成功/失败/未知指令/平台过滤/超时/不匹配版本均有测试」。逐条落为：

| ID | 类别 | 构造的输入 | 期望结果 | 关键点 |
|---|---|---|---|---|
| **T-H-01** | 成功 | 一个合法的 `// run` 用例（如 `helloworld.go` 的副本） | 判定 `pass`；退出码 `0`；stdout 与 `.out` 一致 | 基线正向路径 |
| **T-H-02** | 失败 | 与 `.out` 不符的输出 / 非零退出码 | 判定为**用例失败**（`compiler-failure` 或 `runtime-failure`，按来源），**不是** harness 崩溃 | 失败必须被**分类**，不能被吞掉 |
| **T-H-03** | 未知指令 | 首行写 `// notarealpattern` | 判定 `harness-failure`，报未知指令；**绝不允许静默跳过或记为 pass** | 对齐 `testdir_test.go:557` 的硬失败语义 |
| **T-H-04** | 平台过滤 | 首行加 `//go:build windows`（或含不满足的 `GOOS/GOARCH`） | 判定 `target-filtered`，**不计入分子、仍计入分母** | 对齐 `03` §3.3「过滤项仍在分母」 |
| **T-H-05** | 超时 | 一个超过设定 wall time 的用例（用 `sleep` 或死循环 fixture） | 判定 `timeout`，且**子进程被真正终止**（无残留） | 需验证进程被回收 |
| **T-H-06** | 不匹配版本 | 把 oracle 指向一个版本不符的 Go（或伪造 `go version` 输出） | **拒绝**该 oracle，报 `reference-toolchain-failure` | 对齐 `04` §7「版本不符即拒绝作基线」 |

**附加要求**（`03` §3.3）：六类测试须**同时有正例与反例**；测试不得依赖网络。

**门禁判定**：T-H-01 ~ T-H-06 全绿。

## 4. E4 —— 官方语料基线样本（20 个，**冻结**）

### 4.1 分层与选取标准

`03` §4 要求「至少 20 个**按模式分层**的确定性样本」。分层结果：

| 模式 | 数量 | 占比 |
|---|---:|---:|
| `run`（无参数） | 8 | 40% |
| `compile`（无参数） | 4 | 20% |
| `errorcheck`（无参数） | 8 | 40% |
| **合计** | **20** | 100% |

**选取标准**（全部满足）：

1. 首行为**无参数**的裸指令（无 `-gcflags`、无 `-d`、无 `output`、无 `dir`）；
2. **无并发**（不含 `go` 语句、`chan`、`select`）—— 对齐 `03` §3.4「M0 只纳入无外部时序依赖的 fixture」；
3. **无 `import`「os/exec」「time」「sync」**，不依赖外部资源；
4. 体积小、结构简单，便于人工核对；
5. 不涉及 `unsafe`、`reflect`、`cgo`、汇编内联。

**明确排除**的典型：

| 用例 | 排除理由 |
|---|---|
| `struct0.go` | 含 `go recv(c)` 与 `chan`（并发） |
| `align.go` | 含 `//go:noinline` 且有 32/64 位架构依赖注释 |
| `deferprint.go` | 输出含 `chan`/`map`/`func` 的 nil 表示，属实现细节 |
| `sigchld.go` | 依赖信号 |
| `env.go` | 依赖环境变量 |
| `reflectmethod*.go` | 依赖 `reflect` |
| `unsafe_*.go` | 依赖 `unsafe` |
| `rotate*.go`、`index*.go` | 实为 `runoutput` 模式（生成器），非 `run` |

### 4.4 `errorcheck` 层样本（8 个）

判定：诊断条目集合与 ERROR 期望**逐条匹配**（规则 R3 + R4）。M0 阶段比较器只对齐**拒绝/接受 + 位置 + 预定义类别**，文本正则另计指标（`03` §3.4）。

| ID | 路径 | 体积 | 覆盖点 | ERROR 条数 |
|---|---|---:|---|---:|
| **T-C-13** | `test/initloop.go` | 408 B | 初始化循环检测；**跨行正则**（`\n.*`） | 1 |
| **T-C-14** | `test/recover5.go` | 408 B | `recover` 参数数量；**同行 1 个 OK + 2 个 ERROR** | 2 |
| **T-C-15** | `test/varerr.go` | 449 B | 未定义标识符；内建 `new` 误用 | 2 |
| **T-C-16** | `test/convlit1.go` | 458 B | 复合字面量非法；**多备选模式**（`a\|b\|c`） | 3 |
| **T-C-17** | `test/init.go` | 479 B | `init` 不可被引用；含 `undefined: runtime` 备选 | 3 |
| **T-C-18** | `test/switch4.go` | 526 B | `fallthrough` 出现在最后一个 case | 1 |
| **T-C-19** | `test/typecheck.go` | 543 B | 参数列表中的未定义类型；参数数量不足 | 4 |
| **T-C-20** | `test/mainsig.go` | 598 B | `main`/`init` 签名；**同一行两条 ERROR** | 4 |

**各样本的 ERROR 期望原文**（供 harness 单测直接引用）：

```text

                         // ERROR "compos"
                         // ERROR "conver|incompatible|invalid"

T-C-18 switch4.go        // ERROR "cannot fallthrough final case in switch"
T-C-19 typecheck.go      // ERROR "undefined.*b"   ×2

                         // ERROR "undefined.*c|not enough arguments"
```

**这 8 个样本刻意覆盖的语法特性**：跨行正则、同行多 ERROR、备选模式、`////` 禁用、OK 与 ERROR 混排 —— 即规则 R4 的全部要点。

### 4.5 比较器规格

| 模式 | 比较器 | 说明 |
|---|---|---|
| `run` | **stdout 精确字节比较**（`\r\n`→`\n` 归一化后）；退出码 `== 0` | 规则 R2。**分别捕获 stdout / stderr**，不得混流 |
| `run` | stderr 期望为**空**（本批样本均无 stderr） | 实测确认 |
| `compile` | 仅退出码；**不比较任何输出** | `03` §3.4：不得默认把输出当 stdout |
| `errorcheck` | 先对齐**拒绝/接受**；再对齐**位置**（`文件:行号` 前缀）；文本正则匹配单列为指标 | 直接复用规则 R3 + R4 |

| U6 | `errorcheckoutput`、`errorcheckandrundir`、`errorcheckwithauto` | `expected-unsupported` | 组合模式 | 后续 |
| U7 | 带 `-gcflags` / `-d` / `-goexperiment` / `-godebug` 参数的用例 | `expected-unsupported` | 编译器内部开关，非语言语义（`03` §3.1） | 不定 |
