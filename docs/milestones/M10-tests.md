# M10 判据清单：精确 STW GC

> **怎么用**：`M10-design.md` 说「建什么」，这里说「怎么验」，`M10-plan.md` 说「怎么干」。
> 每条判据都要能回答两个问题：**① 它测的是哪条门禁？② 实现错的时候它会不会红？**
> 第二个问题答不上来的，就不是判据（M9 的三条「变异绿」是这笔学费）。

---

## 0. 三态语料（所有判据的地基）

| 态 | 环境 | 期望 | 它证明什么 |
|---|---|---|---|
| `off` | `RGOC_GC=0` | 69/0/0 | 关掉 GC 之后行为与 M9 完全一致（`GC-2`）|
| `on` | 缺省 | 69/0/0 | 自动触发下输出不变（`GC-6`）|
| `stress` | `RGOC_GC_STRESS=1` | 69/0/0 | **根扫全了** —— 每次分配都收，任何漏扫都会立刻变成悬垂指针（`GC-3`）|

`stress` 是最便宜也最强的判据：69 个真实程序 × 每次分配一次 GC。它过了，
「根集合漏了一类」这件事基本不可能发生。

---

## 1. `GC-1` 对象头与块形状

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-HDR-01` | `new(T)` 读字段 0 是零 | `new(S)` / `new([2]int)` / `var r *S; r = new(S)` 三处都是 `0`。**已实现**（`R-10-1`，`mem_alloc::new_出来的对象读字段_0_是零`）|
| `T-HDR-02` | 块头 16 字节且 16 对齐 | `p := new(int); q := new(int)` ⇒ `uintptr(q) - uintptr(p)` 是 **16 的倍数**且 `>= 24`；两个指针都 16 对齐。判据不写死 32（分配器可以在中间留 padding），但**必须** ≥ 24 且对齐 |
| `T-HDR-03` | 四种 kind 的块头自洽 | C 侧 `_Static_assert` + 探针：`rt_gc_probe_kind(ptr)` 对 object/array/closure/raw/mapslots 各返回预期值（fixture 里各造一个，用探针打出来）|

## 2. `GC-2` 托管堆

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-HEAP-01` | 分配-释放-再分配 500 轮 | 每轮 `p := new([64]byte); 写入校验值`；下一轮分配可能复用同一块 ⇒ 校验值必须是本轮写的（**复用要清零**）。最后 `live_bytes` 不随轮数增长 |
| `T-HEAP-02` | `RGOC_GC=0` 与 M9 等价 | 69 语料逐字节一致；且 `rt_heap_used()` **单调增**（关掉 GC 就没有复用）|
| `T-HEAP-03` | chunk 16 MiB 对齐 | 探针 `rt_gc_probe_chunk_unaligned()` 恒 0；`rt_gc_probe_chunks()` 与 `heap_committed / chunk_size` 自洽 |
| `T-HEAP-04` | first-fit 与切分 | 先分配一个大块、释放、再分配三个小块 ⇒ 三个都能装进那个洞（`live_bytes` 不涨、`heap_committed` 不涨）；余量不足时不切分（不产生 < 32 字节的碎片块）|
| `T-HEAP-05` | 块跨页 | `make([]byte, 1<<20)` 的尾指针（`&s[1<<20-1]`）能被 `mark_ptr` 正确解析回块首（探针 `rt_gc_probe_resolve(p)` == 块首）|

## 3. `GC-3` 精确根（七类各一条）

| ID | 根 | fixture（Go）| 期望 |
|---|---|---|---|
| `T-ROOT-09` | 栈（单帧）| `p := new(int); *p = 7; churn(); println(*p)` | `7` |
| `T-ROOT-10` | 栈（**逐位点**）| 同一函数里：`p` 在 A 点活、B 点已死；B 点触发 GC；随后 `*p` **不该**被保证（改成断言 `bad_ptr == 0` 且程序不崩）| 输出稳定 + 计数器 0 |
| `T-ROOT-11` | 栈（三层）| `f` 里 `p`，调 `g`，`g` 调 `h`，`h` 里 `churn()`；返回后 `*p` 仍是原值 | 原值 |
| `T-ROOT-12` | 全局 | `var G *[1024]byte`；`G = new(...)`；`churn()`；读 `G[0]` | 原值 |
| `T-ROOT-13` | defer 的 `fv` | `f := func(){ println(*p) }`（闭包捕获 `p`）；`defer f()`；`churn()`；返回时打印 | 原值（闭包块与 `p` 都没被收）|
| `T-ROOT-14` | panic 值 | `defer func(){ if r := recover(); r != nil { println(r.(*T).n) } }()`；`panic(&T{5})` + `churn()`（在 defer 里 churn）| `5` |
| `T-ROOT-15` | map 槽 | `m := map[string]*[64]byte{}`；`m["k"] = p`；`churn()`；`m["k"][0]` | 原值 |
| `T-ROOT-16` | 闭包捕获 | `p := new(int); f := func() int { return *p }; churn(); println(f())` | 原值 |
| `T-ROOT-17` | 数组元素 | `s := make([]*[64]byte, 4); s[2] = p; churn(); s[2][0]` | 原值 |

> **为什么七类要分开写**：它们是**七段不同的扫描代码**（帧链 / 全局表 / defer 链 /
> panic 状态 / map slots / closure / array）。合成一条「都活着」的用例，
> 漏掉任何一段都还是绿的。

## 4. `GC-4` 精确性（「精确」二字的唯一强证据）

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-PREC-01` | **整帧扫描会崩** | 槽里放一个「像地址但不是对象起点」的整数：`u := uintptr(unsafe.Pointer(p)) + 8`；然后 `churn()`。保守扫描会把 `p+8` 当对象解引用（读到邻居块头）⇒ 崩或算错；精确扫描下 `u` 不在位图里 ⇒ 不崩、输出稳定 |
| `T-PREC-02` | 死局部被回收 | `func f() { for i:=0;i<1000;i++ { _ = new([4<<10]byte) } }`；`f()` 之后 `rt_gc_live_bytes()` 必须**回到基线附近**（< 64 KiB）。这条钉「不过度保留」|
| `T-PREC-03` | `uintptr` 不是根 | 与 M9 的 `U-M9-10` 守卫对齐：`u := uintptr(unsafe.Pointer(p))` 之后把 `p` 置 nil，`churn()`，`live_bytes` 降（`u` 没保住对象）|

## 5. `GC-5` 触发与统计

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-GC-01` | 阈值触发 | `RGOC_GC_THRESHOLD=65536` + 分配 1 MiB ⇒ `collections >= 1`（探针）|
| `T-GC-02` | 统计行格式 | `RGOC_GC_STATS=1` ⇒ stderr 恰好一行，形如 `gc: collections=3 allocs=1200 frees=1100 live=8192 heap=16777216`；**stdout 一个字节都不多** |
| `T-GC-03` | 压力模式 | `RGOC_GC_STRESS=1` ⇒ `collections >= allocs`（每次分配都收）|
| `T-GC-04` | 不可达被收 | 见 `T-PREC-02`；另加「分配-丢弃 1000 次后 `live_bytes` 不涨」|
| `T-GC-08` | 确定性 | 同一程序跑两次，`collections` / `live` / `heap` 三个数**完全相同**（GC 的时机由分配序列决定，与时间无关）|

## 6. `GC-6` 零回归

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-CORP-05` | 三态语料 | 见 §0；三态各 69/0/0，且三态之间**逐字节相同** |
| `T-CORP-06` | `--via=ssa` 不受影响 | 69 绿（GC 不碰解释器）|
| `T-CORP-07` | 并发语料 | `run-chan.sh` 仍 7/12/0（M8 面，与 GC 无关）|

## 7. `GC-7` 长跑与碎片

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-GC-05` | 长跑有界 | 1e5 次 `new([1 KiB])`（总分配 100 MiB）⇒ 完成不 OOM；`live_bytes <= 2 MiB`；`heap_committed <= 64 MiB` |
| `T-GC-06` | 碎片（**只测不修**）| 交替分配 64 B / 4 KiB 各 5000 次，然后只分配 64 B ⇒ `heap_committed` 不超过「理论最小值 × 3」。超了就**记录**（`U-M10-08`），不修 |
| `T-GC-07` | OOM 语义不变 | `RGOC_HEAP_MAX=4194304` + 长跑 ⇒ `runtime error: out of memory (heap limit 4194304 bytes)` + 退出 2（文本与 M9 一字不差）|
| `T-GC-09` | RSS 记录 | 长跑前后读 `/proc/self/statm`（或 `getrusage`），把数字写进报告。**不设下降判据**（roadmap 原话）|

## 8. `GC-8` 守卫（钉住「现在的实现没有这些东西」）

| ID | 名称 | 判据要点 |
|---|---|---|
| `T-GC-10` | **没有寄存器根** | 一条 fixture：活值只在寄存器里跨过一次调用是不可能的（每个值有槽）⇒ 断言「把某帧的位图全部清空后程序会错」反过来证明位图真的被消费。另一半：`isel` 里**没有**任何 `stp x19..` 的保存点（扫 `.s`）|
| `T-GC-11` | arena 里没有指向堆的指针 | 扫 `rt.c` 的 `rt_arena_alloc` 调用点，逐条在 `C12` §6 列表里登记；未登记的调用点让判据红（源码扫描，沿 `T-SCH-04` 的做法）|
| `T-GC-12` | 三个自检计数器 | 三态语料 + 全部 fixture 跑完，`bad_sp` / `bad_ptr` / `bad_desc` **全为 0** |

## 9. `GC-9` 变异（12 条，每条必须实证变红）

| # | 变异 | 必须变红的判据 |
|---|---|---|
| `M-M10-01` | 块头的 `n` 与 `kind` 交换位置 | `T-ROOT-17`（数组按 object 扫 ⇒ 元素丢）|
| `M-M10-02` | 分配时不置起始位 | `T-HEAP-01`（复用后解析不到块首）|
| `M-M10-03` | 清扫不合并空闲块 | `T-HEAP-04` / `T-GC-06` |
| `M-M10-04` | 标记位不写（`mark` 变空操作）| `T-GC-04`（全都收掉 ⇒ 立刻崩）|
| `M-M10-05` | `mark_ptr` 去掉「在堆里吗」的判定 | `T-PREC-01`（把 rodata 地址当对象）|
| `M-M10-06` | 帧记录不链（`prev` 恒 0）| `T-ROOT-11`（三层帧只扫到最内层）|
| `M-M10-07` | `sp_idx` 恒 0 | `T-ROOT-10`（扫错位点）|
| `M-M10-08` | 位图的 bit 序反向 | `T-ROOT-09` |
| `M-M10-09` | defer 的 `fv` 不扫 | `T-ROOT-13` |
| `M-M10-10` | map slots 不扫 | `T-ROOT-15` |
| `M-M10-11` | 数组只扫第 0 个元素（不乘 n）| `T-ROOT-17` |
| `M-M10-12` | 复用块不清零 | `T-GC-04`（读到上一条命的指针 ⇒ 误标或崩）|

> **「变异绿」先分辨成因**（M9 的学费）：① 判据缺形态；② **探针打错靶**。
> 每条变异先写「它改的那段代码，由哪个用例**执行**」，再跑。

## 10. 不变式（`C12` 的硬约束，逐条要有判据）

| # | 不变式 | 谁来查 |
|---|---|---|
| `H1` | 每个块的 `data` 16 对齐，块大小是 16 的倍数 | `T-HDR-02` + C 侧 `_Static_assert` |
| `H2` | 起始位图的每个 1 都对应一个块首；每个块首的位都是 1 | `T-GC-12` 的 `bad_ptr`（清扫时顺带自检）|
| `H3` | 活块的 `desc` 非空且 `kind` 合法 | `bad_desc` 计数器 |
| `H4` | 帧记录的 `sp_idx < fi->n_sp` | `bad_sp` 计数器 |
| `H5` | GC 期间不分配 | 源码扫描：`mark_*` / `sweep` 里不出现 `gc_alloc`（`T-GC-11` 的同款守卫）|

## 11. 与 M5–M9 的判据边界

| 面 | 边界 |
|---|---|
| M5 解释器 | **不变**。GC 只在 native；`--via=ssa` / `--via=hir` 一字不改 |
| M6 `SSA-LIVE v1` | 位点顺序是 M10 的输入；M10 **不改** `live.rs` 的语义，只加一个 `index_of` 查询 |
| M7 `FRAME-MAP v1` | 帧顶多 24 字节 ⇒ 偏移整体下移；**行语法不变**，`native_frame_map` 的 objdump 对账照旧 |
| M9 `STACK-MAP v1` | 位序与行语法**不变**；`RtFuncInfo` **不加字段**（`sp_words` 是导出量）|
| M8 并发 | native 仍无 goroutine；GC 不碰 `--via=ssa` 的调度器 |
