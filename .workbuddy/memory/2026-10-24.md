## M6 Task 22–25（if / for / switch / goto，控制流全打通）

- **块参数布局 `ParamLayout`**（槽在前、mem 在后）统一 header / latch / exit / goto 标签块；
  任何跳转都用同一个 `args_for` 算实参。`join_into`（N 路合流，值与 mem 都合）是 `if`/`switch`/标签块共用内核。
- **Task 25 的硬决定 `R-25-1`**：含 `goto` 的函数**一律不提升**（全走内存）。非结构化跳转的目标块参数
  在跳转时常常还没定，提升后的回边带不进新值（type/支配全对、verifier 全绿）。全走内存后值住帧里。
- **五个实测真错**：① 类型判等比下标（`add_basic` 不去重）；② 隐式转换要在写入点物化；

  ⑤ `stmts()` 终止后 `break` 会跳过后面的标签（Go 的不可达只到下一个标签）。

## M7 Task 8：对象布局与值分类（两个新发现）

**`R-8-1`（设计稿指向了不存在的东西）**：§7.3 写「偏移一律来自 `rgoc-types` 的布局」，
但 `rgoc-types` **一行布局代码都没有** —— 解释器用字段**下标**（`Value::Struct(Rc<Vec<Cell>>)`），
从来不需要字节偏移。⇒ 新建 `rgoc-types/src/layout.rs`（不是放 arm64：M9/M10 也要用）。

**布局的每个数字都是实测的**（`go run` + `unsafe.Sizeof/Alignof/Offsetof`，2026-10-24）：
- `complex64` align = **4**（不是 8）；`[0]int` = 0 字节但 align **8**
- `struct{a int64; b struct{}}` = **16**（末尾零大小字段 +1 字节再向上取整）
- `struct{b struct{}}` = **0**（同一条规则**不适用**：前提是前面已有非零内容）
- `struct{a struct{}; b int8}` = 1，`Offsetof(b)=0`（前导零大小不占位）
- `interface{}`/`error` = 16/8；`string` 16/8；slice 24/8；`complex128` 16/8

**`R-8-2`**：C5 §6.1 原写「complex 占 2 个 v」不够精确 ⇒ `complex64` **1 个 v**（两个 f32 打包）、
`complex128` **2 个 v**。照原写法会多占寄存器、实参顺序错位。

**顺带记下 `zerosize.go` 的硬要求**：`new([0]int)` 两次必须拿到**同一地址**（官方是 `runtime.zerobase`）
⇒ `rt_arena_alloc(0)` 必须返回**固定哨兵**，零大小全局也落在同一地址。已写进 C5 §7.2。

**计数**：`rgoc-types` layout 15 条、`rgoc-arm64` abi 11 条；**全量 1904 passed / 0 failed / 4 ignored**
（M6 收口 1859 + 45 新增）。commit `dcc53de`。

## M7 Task 11：FRAME-MAP v1 —— **抓到 M6 的一个漏根缺陷（`R-11-1`）**

写 `T-NAT-51` 时先按 `C5` §8 渲染帧图，测试报 `offs=[-24] ptrs=[]`（少了指针 v1）。
追下去发现 `rgoc_ssa/src/live.rs` ④ 的反向扫描：

```rust
let mut cur = live_out[bi].clone();   // ← 少了终止符的读
```

`live_out` 只由**后继**的 `live_in` 与边实参构成，而终止符不是指令 ⇒
**「只在本块终止符里被读」的值**（`return v1` / `if cond` / 无后继块的边实参）
在 `after[]` 里整个消失 ⇒ safepoint 的 `live`/`ptrs` **漏根**。
M6 的 5 条 liveness 测试没抓到：那些用例的返回值同时也被别的指令用过。

**修复**：`cur = live_out ∪ term.uses()`。加两条回归（`rgoc-ssa/tests/live.rs`）：
`r_11_1_只在_return_里用的值仍跨过_safepoint_活着` / `r_11_1_只在_goto_边实参里用的值也算活着`。
**变异验证**：去掉修复 ⇒ return 那条必红（实测），goto 那条两向都绿（它走 `live_out`，
正好证明「两条路都得对」）。`cargo clean -p rgoc-ssa` 后再跑，防产物陈旧。

`R-11-2`：`C5` §8 的 `type=` 改成 `t<id>`（原示例写 `int`/`complex128` —— 那要再造一个
类型渲染器，必然与 `C7` 漂）。

**计数**：`rgoc-arm64` 44 条（+frame_map 6）、`rgoc-ssa` live 8 条；
**全量 1928 passed / 0 failed / 4 ignored**。commit `c8de497`。
**下一步 = Task 12（并行拷贝 + 环检测）。**

3. `.Ldiv0` 发了没定义 ⇒ 每个含除法的程序链接失败
4. `new(T)` 也是 `Instr::Make`，被当 `[]T` 拒 ⇒ 按 `typ` 是否指针分流到 arena

**`R-13-1`**：无类型常量按 Go **默认类型**取布局（`print("hi")` 的实参就是 `untyped string`；
后端不认它，整类程序编不出来）。`nil` 仍 `None`。
