  ① `V3` 判据要认未类型化类型；② M6d 的 fold pass 能折的比想象少。

## M6 Task 22（if/else + 块参数）

- `stmt_if`：汇合块**后建**（先建 then/else，两侧建完才知道要不要 join），再回填 `Goto{args}`。
- **并行交接天然成立**：块参数实参是 SSA 值，边上没有先后；真正的风险在 `ssa_exec` 与 copy pass。
- **两个真问题**：① `add_basic` 不去重 ⇒ 同一个 `int` 有多个 `TypeId`（`1`/`2` 拿到 t45/t46）⇒
  类型判等一律 `identical`，别比下标（`R-22-1`）；② 隐式转换要在**写入点/返回点**物化
  （`untyped int` → 槽类型），否则同一槽两分支带不同 TypeId（`R-22-2`）。
- 变异 4/4 红；161 suite / 1700 passed。下一站 Task 23（for 三形态 + 回边）。

## M6 Task 22–25（if / for / switch / goto，控制流全打通）

- **块参数布局 `ParamLayout`**（槽在前、mem 在后）统一 header / latch / exit / goto 标签块；
  任何跳转都用同一个 `args_for` 算实参。`join_into`（N 路合流，值与 mem 都合）是 `if`/`switch`/标签块共用内核。
- **Task 25 的硬决定 `R-25-1`**：含 `goto` 的函数**一律不提升**（全走内存）。非结构化跳转的目标块参数
  在跳转时常常还没定，提升后的回边带不进新值（type/支配全对、verifier 全绿）。全走内存后值住帧里。
- **五个实测真错**：① 类型判等比下标（`add_basic` 不去重）；② 隐式转换要在写入点物化；
  ③ `stmt_if` 只合 `val` 不合 `mem`（分支里的 Store 被摘出 mem 链，V6 抓到）；④ 提升判据用末尾 `must`（循环体内声明的槽 panic）；
  ⑤ `stmts()` 终止后 `break` 会跳过后面的标签（Go 的不可达只到下一个标签）。
- 变异本轮 +20 全红（22:4 / 23:5 / 24:6 / 25:5）。
- 数字：161 suite / **1717 passed**；`ssa_build.rs` 38 条。下一站 Task 26（多返回值直连）。
