## 踩的坑（值得记住的）

1. **两个容器同时跑变异脚本** ⇒ 抢同一个 `crates/rgoc-driver/target/obj-map/`
   的可执行文件，一边执行一边被改写 ⇒ 99% CPU 烧 28 分钟，既不红也不绿。
   `cargo` 有 target 锁，但**测试跑起来的产物**没有 ⇒ 脚本加 `mkdir` 原子锁。
2. **中断会把变异留在工作树里** ⇒ 下一轮第一条探针报 MISS（锚点已被自己改掉）。
   脚本加 `trap ... EXIT INT TERM` 还原。
3. **卡死不是判据** ⇒ 每条探针 `timeout`，单独记 `HANG` 一栏。
4. **`M-M12-09` 首版锚点的「卡死」不是探测逻辑**，是 `low_bit_index(0)` 死转
   （`first_del` 的记录在 `emp` 判定之后）。判别实验（再给 `low_bit_index` 加 0 兜底）
   把「卡死」变成「语义红」⇒ `G-M12-05`。
5. **`manifest.measured` 是自报**：`manifest_m12.rs` 现在要求每条 c 线读数**带数字**，
   只写「下降了」会红。
6. **改测试文件时正在跑的全量**会编到旧版 ⇒ 全量里那条红是假红，单跑复核才是证据。
