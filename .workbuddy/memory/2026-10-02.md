### 推送过程中发现并修复的两个真实缺陷（已改进技能脚本 `push_via_api.py`）

1. **空仓根提交**：脚本原按「快进推送」设计，`GET /git/ref/heads/main` 在空仓返回 409 直接崩溃 → 新增 `--root` 模式，并把 `ref_exists` 改为始终探测（否则会误用 POST 建 ref 而报 422）
2. **GitHub Git Data API 硬限制**：**完全空的仓库拒绝 `POST /git/blobs`**，返回 409 `Git Repository is empty` —— 与网络无关，是平台约束。解法：先用 Contents API 造一个引导提交使仓库非空，再用 `--root` 把 ref 强制指向本地根提交

- 校验结果：远端 `ref main` 与本地 HEAD **SHA 完全一致**（`762b4ae0a66d814d0caaaeee2293a63d31b056a9`），tree 亦一致（`2f367ffe7473eb55f8205474438276ff71c777ab`）；远端 11 个文件体量逐一核对无误
- 引导提交转为 unreferenced（仅含 1 字节占位，无敏感信息）
- 收尾：补设 `branch.main.remote` / `branch.main.merge` 上游跟踪（因 `git push -u` 未成功），`git status -sb` 现显示 `## main...origin/main`
