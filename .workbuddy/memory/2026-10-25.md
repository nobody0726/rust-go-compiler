## M7 阶段二：语料从 25 → 39 全绿（native 与官方 oracle 逐字节一致）

起点：46 个 `N` 文件里 25 个能跑、12 个语义错。逐一追到根因，全部是**真错**不是环境。

**修掉的错（每条都先跑出真红/真错）**
1. **方法接收者被丢**（`isel::call` 的 `let _ = recv;`）→ `func.go`/`robfunc.go` 段错误。
   接收者是 `Func.params[0]`，`CalleeRef::Method` 把它单独放一个字段，必须自己拼回去。
2. **切片面的洞**：`[]T{...}` 复合字面量没被拒 ⇒ `composite()` 按数组算偏移，
   第 0 项写到切片头的**数据指针**上。改成 `func_has_slice()` 在**发第一条指令之前**
   按**类型**扫（值/取址槽/`Make`/`Composite`），一处判据覆盖完整边界。
   顺带把 `CgCode` 的退出码从 2 改成 1（静态拒绝 ≠ 内部失败）。
3. **字符串比较/拼接是指针运算**（静默错）：`bin` 先按 `is_string_ty` 分流，
   比较走 `rt_strcmp`（按**无符号字节**）、拼接走 `rt_strcat`（16 字节 `{ptr,len}` 按
   AAPCS64 用 `x0/x1` 返回）。同时补 `rt_i64_to_str`（`string(int)` 的 UTF-8 语义）。
4. **`len(s)` / `cap(s)` / `min` / `max` / `complex` / `real` / `imag` 全是空实现**
   （`builtin()` 直接 `Ok(())`，dst 永不写）。补齐。
5. **形参绑定漏第二字**（`bind_params` 的 `Int` 只存一个 `x`）⇒ `string` 形参丢长度，
   表现为「内容对但比较/拼接全错」，`+"b"` 触发 `panic: out of arena`。
6. **窄类型符号扩展用 `sxtw`**（32 位）而不是按自身宽度 ⇒ `int8(-128)` 读成 `128`。
7. **`complex64` 是 HFA**（`R-13-2`，推翻我昨天写的 `R-8-2`）：两个 `s` 寄存器，
   不是打包进一个 `v`。`konst` 的复数常量步长也要按类型选（4+4 / 8+8）。
8. **调用点的寄存器分类必须按被调方形参**（`R-13-3`）：无类型复数的默认类型是
   `complex128`、形参却是 `complex64` ⇒ 被调方读到 `d0` 的低 32 位（0）。
   精度不同在边界做 `fcvt`。
9. **帧太小**（`R-13-4`）：`sub sp` 必须覆盖到**最低槽**。原写法让 `sp` 比最低槽高
   16 字节，被调方的 `stp x29,x30,[sp,#-16]!` 正好盖住「最后一次写入的槽」。
   46 个语料里 32 个照样绿 —— 这个错只在「函数里有调用」时才现形。
10. **比较按 `dst` 分类**（比较结果是 `bool`）⇒ 浮点比较变成「位模式比大小」。
    改成比较按**操作数**分类。
11. **整数值的浮点常量**（`const 35 : float32` 的 `ConstVal` 是 `Int`）被当整数装槽。
12. **聚合的 `==`/`!=` 没实现**（`Agg` 分支空）⇒ `*p != x`（`[2]int`）恒 panic。补 `rt_memcmp`。
13. **边上的并行拷贝只搬一个字** ⇒ `string` 的块参数丢 `len`（`simpswitch` 的
    `switch` 每个 case 都是一条边）。改成按**字**展开再排。
14. **字符串下标按 8 字节步长** ⇒ `prog[pc]` 全读错（`turing.go` 一个字符都不执行）。
15. **移位计数不钳制**：AArch64 的 `lslv/asrv` 只取低 6 位，Go 规定 n ≥ 位宽时结果为 0
    （`asr` 则全是符号位）。`1234 << 1025` 变成 `2468`。
16. **`panic(浮点)` 打位模式**（`1107296256`）⇒ 加 `rt_panic_f64` / `rt_panic_complex`，
    与 `println` 共用一份格式化（`g_out_fd` 切通道）。
17. **零大小对象的唯一地址**：`rt_zerobase` 由生成的 `.s` 定义（`.global` + `.data`），
    零大小全局用 `.set g<id>, rt_zerobase` 别名 —— 「同一个地址」只能有一处来源。
18. **`extra_slots` 没进 `SsaFunc.slot_types`** ⇒ `&CompositeLit` 的落点没有帧存储，
    `addr-of` 读一个没写过的槽 ⇒ `compos`/`newexpr` 段错误。
19. **地址逃逸**（`R-13-5`）：逃逸的取址槽进 arena（帧里只留 8 字节指针格）。
    保守判定：`return` / 传给非内建函数 / 写进全局或堆。

## M7 `G-M7-01` 关闭：9 个以上实参的 outgoing 区（`R-13-6`）

**病**：`pass_args` 把第 9 个起的实参写 `[sp, #k]` —— `sp = fp - sub`，那是**本方帧内部**
（`[sp,#0]` 起就是最低的槽），既覆盖自己的值，被调方从 `[fp+16]` 读到的也是垃圾。
语料里几乎没有 ≥9 实参的函数，所以 39/39 全绿也没抓到。

**修法（三处，都用同一张表）**
- `abi::place_args(tt, want) -> (Vec<ArgLoc>, u32)`：按 AAPCS64 C.14 给每个形参
  `X{reg,n}` / `V{reg,n}` / `Stack{off}`。**两套寄存器独立计数**；溢出**不清空**计数
  （后面更小的实参仍可进寄存器）；聚合按指针只占 1 个 `x`。
- `frame::outgoing`：全函数所有调用点里最大的栈区字节数，**加进帧的最底部** ——
  只有最底部成立，因为 `pass_args` 写的是 `[sp, #k]`。
- 调用方 `pass_args` 与被调方 `bind_params` 都调 `frame::callee_param_tys` +
  `place_args`，**不许各写一遍**（各写一遍就是 `string` 的两字与 `complex64` 的两 `s` 错位）。

**判据强度要分清**：`twelve_args`（4 个栈字 = 32 B）是硬判据 ——
变异「`max_outgoing` 恒 0」实测变红；`ten_args`（2 个栈字 = 16 B）是**软**的，
帧底恰好有 16 B 对齐余量时它「碰巧绿」。这条写进了测试注释。

**顺带发现 `G-M7-08`（上游，M6）**：聚合**按值**形参根本没对 ——
`build.rs` 把 `func f(s S)` 的形参类型记成 `*S`、home 槽存指针，但 `s.N` 的
place lowering 仍 `addr-of 槽` 再 `field`，把 `&slot` 当 `&S`：读出来是指针位模式、
写进去覆盖指针。实测 `struct_by_value` 红了（native 出 19 位垃圾数，解释器 1001）。
**没有**写「把错误行为钉成期望值」的用例 —— 那种测试比没有更坏。已登记为 `G-M7-08`。

**门禁**：`NAT-3` 由 partial → **pass**（现在 4 pass / 5 partial）。
`G-M7-01` 进 `closed_gaps`；`G-M7-07`（栈对齐）折进 `G-M7-02`。

读数：**1961 passed / 0 failed / 1 ignored**。

## M8 三件套就位（设计 → 判据 → 计划，全部签字确认）

用户「先讨论下 M8 的设计和计划吧（用 superpowers 插件）」⇒ 走 brainstorming 的
architectural 路径：名词表 → 实测基线 → 四个拍板项 → 分节设计 → spec → 判据/计划。

**四个签字（全按建议）**
1. 状态切分 = **抽 `G`**（方法挪到 `impl G`，`Shared` 作参数）。银行切换被否：
   加一个 per-G 字段忘 swap 就是静默串味（M7 整里程碑在抓那类错）。
2. 调度 = **确定性 FIFO + seed 只选 select**。不做事件日志（冗余）。
3. M8d = **range-over-func 先做窄面**（body 下沉合成函数；`return`/`goto` 静态拒）。
4. 语料 = import-free + 自有 fixture。

**实测抓到的新事实（全部进 `M8-design.md` §2.3 F1..F16）**
- **`check` 面已经放行并发**（0 诊断）；唯一挡路的是 HIR lowering 的 5 个 reject。
  ⇒ M8 的主战场不在类型系统。
- **`v, ok := <-c` 是 check 的真 bug**（报 `CHK-INVALID-ASSIGN`），而 Go 合法。
  `perm.go` 里就标着 `ok`。⇒ Task 51。
- **69 个冻结语料里 0 个用并发**（`turing.go` 的 `<-` 是 Brainfuck 字符串里的）。
- `test/chan` 19 个：8 个 import-free，但 **`perm.go` 是 `// errorcheck`（官方也编不过）**
  ⇒ 可跑 **7**，不是签约时算的 8。这条登记为 `measurement_deviations`。
- **那 7 个官方跑完 stdout 全 0 字节**，但 **5 个自带断言**（`sieve1` 用链式 goroutine
  验 25 个素数，算错就 `panic("fail")`）⇒ 「退出码 0」在并发语料上比 M7 强一档。
- 解释器 per-G 状态 **300 处** `self.xxx`（一处不用改）、共享面 **64 处**（要改）。

**三个关键设计（写 code 前必须记住）**
1. **阻塞 = 任务不弹出**：`Task::Recv/Send` 留在求值栈顶，醒来重试同一个任务；
   判据是 `Waiter.done`，不是重试次数。这是「挂起点在表达式中间」的唯一低成本解法。
2. **select 三阶段**（求值 → 试探 → 登记）+ **token 撤销**：重复 channel 的两个
   waiter 只有一个 `done`，另一个靠 token 撤掉。

## M9 / Phase 4a 收口：无捕获的函数值，语料 **60/69**（commit `688add3`）

* **静态 funcval**（`__fv_<fid>: .quad fn`）：funcval 首字必须是 `fn`，间接调用一律

  `x1` 起、`x0` 是隐式 ctx。判据在 `build()` **收尾扫描**（模块级事实，使用点可能在
  被调方之后才建）。**不给全体函数开** —— 改全体 ABI 要动 60 个已绿文件的风险面。
* **免费搭车**：`range` over func 现在真能跑（合成函数无捕获）。
* 拒绝面 57/12 → **60/9**；剩下的 FUNC-VALUE 5 条全要捕获（Task 38）或方法值（Task 41）。

⚠️ **设计偏差（Task 38 必须对齐）**：设计稿 Task 39 写「捕获按值内联」，但
`closure2.go` 整份文件钉的是**按引用**（改要改到外面去）⇒ funcval 里只能放
**指向变量存储的指针**，被捕获变量必须逃逸到堆（`Root::Slot` 的存储本来就在 arena，
所以「有根」就自动逃逸）。已记 `R-9-15` 并写进 `ir.rs::MakeClosure` 文档。

### 手法
守卫测试（`u_m7_02`）按设计变红时**换成正向证据**（真的跑、真的算对）——
「它红的那天，就是补正向证据的那天」。

## M9 / Phase 5a：defer + panic 传播 + recover（commit `db510e6`，语料 65 ok / 3 skip / 1 bad）

**已通**：`closure4` / `defernil` 双通路全绿；`defer`（无实参）、`panic`、`recover`
在 native 与 `--via=ssa` 上都对（三条最小 fixture 逐行一致）。

### 三条设计要点（后面几轮都靠它们）
1. **不 unwind**：`.framemap` 不在 ELF 里 ⇒ 不能 `longjmp` 跳过帧（漏扫根）。
   「`rt_panic` 只置状态 + 每个调用点之后 `bl rt_panicking; cbnz x0, <出口>`」
   就是返回码传播。出口 = 跑本帧 defer + `ret`。
2. **跑 defer 期间挂起 panic**：被 defer 调用的函数是正常执行的，它内部不该看到
   「正在 panic」—— 否则 defer 里调任何函数都会被立刻中断。`recover()` 读的是
   **挂起**的那个。
3. **`recover()` 的返回值只有「非 nil」+「可打印」**（M9 没有 reflect）⇒ 给一个
   指向 panic 文本的 `string` 接口。

### 关键实现细节
* **九个 panic 入口统一改「捕获 + 置状态」**：在 `write_all` 一层拦截（`g_capturing`），
  九个函数各写一套格式化太散；被 recover 掉就不该有输出。
* **退出只在 `_start` 收尾**：`bl rt_panicking; cbz x0, .Lexit0; bl rt_print_panic;
  mov x0,#2; bl rt_exit` —— `C9` §4.5 的唯一出口。
* **`check_panic` 用 `cbnz` 直接跳出口**，不要造「跳过」标签（同一函数多处检查会
  重复定义符号，GNU as 报 `already defined`）。
* **`Term::Return` 必须先跑 defer 再装返回值**：`rt_deferrun` 是 C 调用，会打掉
  `x0..x18` 与 `v0..v7`。

### ⚠️ 未收口：`nilptr2.go`（`G-M9-06`）
要**可恢复的 nil 解引用**：native 给 `Load`/`Store` 加 nil 检查；求值器把 `as_ptr`
的 `NilDeref` 从 `Halt` 改成可恢复 panic（那要 `&mut self`）。另有
`v6 的类型 t35 没有运行期布局`（`func@12:3`，t35 = invalid）待查。
**因此 8 条判据红且故意不重冻结**（同 `ddd.go` 那轮的理由）。

### 顺带：`CompileError::Frame` 带上了函数名
只给 `ValueId` 定位不到（同一个号在几十个函数里都出现过）—— 这次就是靠它才看到
是 `func@12:3`。**诊断信息里缺的往往不是细节而是上下文**。

## M9 / Phase 5b + 5c 第一步（commit `bb4cc9a` / `80f40a3`，语料 65 ok / 1 skip / 3 bad）

### 5b：`defer` 带实参 / 方法 / 内建（`R-9-19`）
`defer <call>` → 「实参**现在**装盒 → 合成包装函数 → `MakeClosure` → `Instr::Defer`」。
* `Fb::box_value`：**长度 1 的 slice 当盒子**（`Composite` + `Index`，不新增 IR）。
  **每次登记都新分配** ⇒ `for { defer println(i) }` 打 `2 1 0`。
* `call_parts`：把 `call()` 拆成「算零件」/「发 Call」——`defer` 要「实参现在求值、
  调用以后执行」，复用同一份变参打包。
* `synth_defer_wrapper`：手搓 SsaFunc，捕获 = 实参盒子 + 被调方自己的操作数
  （接收者 / funcval / 接口值）。

### 顺带修的真 bug：`call_sigs` 的口径
同一个函数既可能被**直接调用**（`(*T).M(x)`，接收者是第 0 个实参）又被**方法调用**
（`t.M(x)`，接收者单列）。按 `FuncId` 一个键存会互相覆盖 ⇒ `V5` 报「给了 1 个，
签名要 0」。**修法：`call_sigs` 一律记完整签名，`V5` 对 `Method` 按 `args+1` 比。**
⚠️ 这类「被别的特性挡住了所以从没跑过」的判据，一旦放行就会暴露既有 bug ——
`method.go` 就是这样。

### 5c 第一步：nil 解引用改成**可恢复** panic（`R-9-20`）
`load`/`store` 取到地址后插 `check_nil_reg`（`cbnz reg, 1f; bl rt_panic_nil;
b <本帧出口>; 1:`，用**数字局部标签** —— 同函数几十处检查，起名会撞）。
之前是硬件 SIGSEGV，`recover` 救不回来。

### 三个 bad 的精确病因（下一步照着修）
1. **`method.go`**：`a.h()`（`A ⊃ B ⊃ *D`，`a.B.D == nil`）Go 会 panic，我们不会 ——
   `h` 是 `D` 的**值接收者**，Go 必须把 `*D` **解引用拷贝一份**（那一步在 nil 上 panic），
   而本后端聚合接收者**按指针传**（`C5` §6.1）⇒ 拷贝被省掉，空方法体什么都不做。
   修法：build 侧给「值接收者 + 聚合」的提升链补一条**显式解引用**。
2. **`nilptr2.go`**：`func@12:3：v10 的类型 t35 没有运行期布局`（t35 = invalid），
   三层嵌套闭包里某值拿到 invalid 类型 —— 构建 bug，待查。
3. **`print.go`**：`println` 打 **nil 接口 / nil map / nil slice**
   （`(0x0,0x0)` / `0x0` / `[0/0]0x0`）我们打空白。既有打印缺口（`C9` §4.3）。
