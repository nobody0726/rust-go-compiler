# M10 变异探针笔记（20 条 + 2 条「该绿」的）

> 纪律（沿用 M9）：**变异 GREEN 先怀疑用例集**，不怀疑代码。这里逐条记实测结果，
> **绿过也写清为什么绿** —— 藏起来的话，下一轮会以为这条判据有牙。

复现：容器内 `bash scripts/mutation-m10.sh` ⇒ 现态 **`RED 20 / 失手 0`**。

## 一、脚本里的 20 条

| # | 变异 | 判据 | 抓的是 |
|---|---|---|---|
| `M-M10-01` | `blk_size_of` 恒 32 | `gc_reclaim::t_gc_04` | 块大小算错 ⇒ sweep 走到块中间 |
| `M-M10-02` | `bm_set` 空实现 | `gc_heap::t_heap_05` | 起始位图是「内部指针回块首」的唯一依据 |
| `M-M10-03` | sweep 把所有块当活 | `gc_reclaim::t_gc_04` | 不回收 |
| `M-M10-04` | 不写标记位 | `gc_reclaim::t_root_12` | 全被回收（含全局根指向的）|
| `M-M10-05` | `mark_ptr` 用 `heap` 顶替 `chunk_of` | `gc_reclaim::t_gc_12` | 非堆地址被当块首 |
| `M-M10-06` | `resolve_block` 不退化 | `gc_heap::t_heap_05` | 跨页内部指针解析不到 |
| `M-M10-07` | 复用的块不清零 | `gc_heap::t_heap_01` | 读到上一条命的数据 |
| `M-M10-08` | 跳过 free list | `gc_reclaim::t_heap_04` | 堆只增不减 |
| `M-M10-09` | `mark_roots` 不扫全局 | `gc_reclaim::t_root_12` | 全局根丢 |
| `M-M10-10` | `Composite` 不是 safepoint | `gc_heap::t_heap_07` | 切片字面量的三个数组互相顶掉 |
| `M-M10-11` | `mapslots` 不扫 | `gc_heap::t_map_11` | map 值里的指针丢 |
| `M-M10-12` | `free_push` 不置起点位 | `gc_heap::t_heap_08` | 假块首 ⇒ 拿旧 desc 扫垃圾 ⇒ 段错误 |
| `M-M10-13` | `mapslots` 不滤 `TOMB` | `gc_heap::t_map_12` | 删掉的条目被钉住（永久泄漏）|
| `M-M10-14` | `mark_defer` 不扫 | `gc_stack::t_root_13` | `defer` 的闭包块被回收 |
| `M-M10-15` | 逃逸槽退回 arena | `gc_stack::t_root_14` | 闭包捕获 `&槽` 时槽里的指针没有根 |
| `M-M10-16` | epilogue 不摘链 | `gc_stack::t_root_11` | 链指向已返回的帧 ⇒ 拿垃圾当 `fi` |
| `M-M10-17` | `sp_idx` 恒 0 | `gc_stack::t_root_10` | 用错位点的位图 ⇒ 漏标 |
| `M-M10-18` | 整帧保守扫描 | `gc_precise::t_prec_01` | 像地址的整数被当根 ⇒ 死对象钉住 |
| `M-M10-19` | 帧位序反（`base = fp - 8`）| `gc_stack::t_root_09` | 扫到帧外的字 |
| `M-M10-20` | 自动触发永不触发 | `gc_longrun::t_gc_01` | 自动态退化成关态 |

`probe_rs`（改 Rust 源码的三条：10/16/17）在恢复后额外 `cargo clean -p <crate>`：
绑定挂载的 mtime 只到整秒，`touch` 之后可能与 rlib 同秒 ⇒ cargo 认为源码没变
⇒ 继续用变异版 rlib（M9 踩过：单跑绿、全量红）。

## 二、两条「该绿」的（写在笔记里，不进脚本）

脚本的约定是「绿 = 失手」，所以这两条不进脚本 —— 但它们的**绿**是证据。

| 变异 | 结果 | 为什么绿是**对的** |
|---|---|---|
| 自动触发 `next = 0`（每次分配都收）| GREEN | 这是「压力与自动**等价**」的证据：stress 态与自动态在语义上一致，只是频率不同。如果它红了，说明「收的频率」影响了结果 —— 那才是 bug |
| `bad_ptr` 把「指向空闲块」也计入 | GREEN（对判据而言）| 保守位图下扫到已死指针是常态（`R-10-21`），所以这条改动只会让 `bad_ptr` 恒非 0、探针失去意义。它不是「代码坏了」，是「口径错了」 |

## 三、绿过的四条（已修，留档）

这一轮**变异绿过四次**，每次成因都不同 —— 这是 M10 最值钱的部分。

| 变异 | 绿的原因 | 修法 |
|---|---|---|
| `M-M10-09` 全局根不扫 | ① `effect.rs` 说 `new`/`make` 纯 ⇒ 整个 `churn()` 被 DCE 删（`allocs=1`）| `R-10-11` 标 `may_panic` |
| 同上（第二次）| ② `gc_alloc` 先 bump 后 free list ⇒ 回收的块从没被复用 | `R-10-12` 换序 |
| 同上（第三次）| ③ churn 用 8 KiB 块，装不进 1040 字节的块 ⇒ first-fit 跳过 | 改成 `new([1000]byte)` |
| `M-M10-17` `sp_idx` 恒 0 | `bad_ptr` 收窄后不再计「指向已回收的块」⇒ 原判据恒真 | 改成读内容（`t_root_10`）|
| `M-M10-16` 帧链不摘 | 三层返回后直接 `println`，没有 GC 去读死链 | 补一段 `churn()` 覆盖死帧内存 |
| `M-M10-13` mapslots 不滤 TOMB | 判据用 `frees >= 190`，而实测 2205 vs 2005 都过 | 改成 `live < 200*80`（从数据推出来的阈值）|

**共同点**：六次里没有一次是「代码其实是对的」。全是**判据的问题**：
被测代码没执行（①）、执行了但没可观察效果（②③）、判据的度量选错（`frees` vs `live`）、
判据的口径随实现演进失效（`bad_ptr`）、判据缺场景（返回后没有 GC）。
